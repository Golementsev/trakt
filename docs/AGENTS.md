# Как устроены агенты в Тракте

Доска — сервер на вашем компьютере (`127.0.0.1:4700`). У него три входа:

1. **Страница** в браузере — то, что видите вы (REST `/api` + живые обновления `/api/events`).
2. **MCP** `/mcp` — через него работают агенты. Это стандартный протокол «модель вызывает инструменты».
3. **Запуск процессом** — кнопка «▶ Агент»: доска сама запускает CLI агента в папке проекта.

Все три входа вызывают одни и те же функции домена (`apps/server/src/domain`), поэтому правила одни
для всех: воркфлоу, «не дальше статуса», пауза, кто держит задачу.

## Два способа, как агент попадает на доску

### Агент приходит сам (pull)

Вы работаете с агентом там, где привыкли: Claude Desktop, Claude Code в терминале, Codex, Cursor.
Один раз подключаете доску как MCP-сервер (готовые команды — на странице «Агенты»), и агент видит её
инструменты: `list_tasks`, `get_task`, `claim_task`, `log_progress`, `complete_subtask`, `move_task`…
Дальше вы просто пишете ему: «возьми PAY-12 с доски Тракт». Агент сам решает, какие инструменты вызвать;
доска отвечает и следит за правилами.

- **Claude Desktop, вкладка Code** и **Claude Code в терминале** — это один и тот же Claude Code
  с общими настройками. Команда `claude mcp add --scope user --transport http trakt http://127.0.0.1:4700/mcp`
  подключает доску сразу к обоим.
- **Claude Desktop, обычный чат** подключает MCP через `claude_desktop_config.json`
  (Настройки → Разработчик → «Изменить конфиг»). Он умеет только stdio, поэтому используется прокси
  `node apps/server/dist/trakt-mcp.js`, который пересылает сообщения на `/mcp`.
- Кто подключён прямо сейчас и что делал последним — видно на странице «Агенты».

### Доска запускает агента (push)

Вы нажимаете «▶ Агент» на сабтаске (или «▶ Все агенту», «▶ Отдать агенту»). Доска:

1. берёт команду выбранного источника со страницы «Агенты» (по умолчанию — Claude Code CLI:
   `claude -p --output-format stream-json --mcp-config … --allowedTools mcp__trakt`);
2. собирает промпт: задача, описание, поля с меткой AI, сабтаски, условие готовности и как отчитываться;
3. кладёт рядом файл `mcp.json` с адресом доски — так запущенный агент получает тот же MCP;
4. запускает команду в папке проекта (или в отдельном git worktree), промпт — в stdin;
5. каждую строку вывода агента пишет в лог сабтаски — вы видите его живьём;
6. когда процесс завершился: если агент сам закрыл сабтаску через MCP — всё, иначе доска закрывает её
   по коду выхода (0 — готово, иначе «не вышло»).

«■ Стоп» завершает процесс вместе с дочерними. Сабтаски одной задачи идут строго по очереди;
в проекте одновременно работает не больше заданного числа агентов.

## Путь задачи по шагам

1. **Вы отдаёте задачу агенту** — кнопкой, переносом в дорожку «Ведёт агент» или просьбой в чате.
2. **Агент берёт задачу** (`claim_task`). Доска помечает «держит Claude Code до 18:40»: второй агент ту же
   задачу не возьмёт. Отметка продлевается, пока агент работает, и снимается в конце.
3. **Читает контекст** (`get_task`): описание, поля, сабтаски, условие готовности и список статусов,
   в которые ему можно перевести задачу.
4. **Работает в папке проекта** — меняет код, запускает тесты.
5. **Пишет прогресс** (`start_subtask`, `log_progress`): на карточке «агент работает», в окне задачи — лог.
6. **Закрывает сабтаски** (`complete_subtask`). После последней доска сама переводит задачу в следующий
   статус «в процессе» (обычно «Ревью»), если это разрешают воркфлоу и «не дальше статуса».
7. **Вы проверяете.** В «Готово» по умолчанию переводит человек. Застрявший агент пишет вопрос
   (`add_comment`) и отпускает задачу (`release_task`).

## AI-функции доски

«✦ Разбить с AI» и идеи из кнопки «+» — не агент, а короткие запросы к модели. Кто отвечает, выбирается
на странице «Агенты»: автоматически, Claude Code CLI (под подпиской, `claude -p`), Anthropic API
(ключ `ANTHROPIC_API_KEY` в `.env`) или выключено. Смена — сразу, без перезапуска доски.
