# Решения и отказы пользователя

Пользователь хочет **простую** канбан-доску. Он резко реагирует на лишние сущности,
поля и выпадающие списки. Всё ниже — его прямые решения по итогам просмотра макета.
Не возвращать отвергнутое без явной просьбы.

## Отвергнуто (не делать)

| Что | Почему / как сказал пользователь |
|---|---|
| Оценка в стори-поинтах | «точно не нужна» |
| Эпики | «это для большой разработки, мне нужна простая канбан-доска» |
| Исполнитель у задачи / сабтаски | Не нужно назначать ни людей, ни конкретного агента. Агент — «что-то, что может просто взять задачу и перенести» |
| Несколько именованных агентов (Coder, Reviewer, QA…) | Агент один, обобщённый. Кто конкретно подключился через MCP — видно в ленте, но не выбирается |
| Приоритет / «Срочно» | «бесит», «на кой хуй это срочно». Никаких приоритетов |
| Выпадающие списки внутри окна задачи | «зачем мне после создания сразу выбирать что-то ещё» |
| Выбор статуса в окне задачи | Статус только **показывается** (степпер). Меняется перетаскиванием на доске или агентом |
| Задача в правой боковой панели | Должна открываться **окном по центру** |
| Критерии приёмки сверху отдельным блоком | Должны быть **под описанием** |

## Принято

- Задача открывается модальным окном по центру.
- Порядок в окне задачи: заголовок → (для новой задачи) выбор типа кнопками → степпер статуса
  (только чтение) → описание → текстовые поля шаблона (критерии приёмки и т.п.) →
  прочие поля шаблона (число/дата/чекбокс) → сабтаски → условие готовности для агента → история.
- Тип задачи выбирается **один раз при создании** кнопками-чипами. Потом только отображается.
- Новая задача — черновик. На доске не появляется, пока не нажата «Создать задачу».
  Кнопки внизу: «Отмена», «Создать и отдать агенту», «Создать задачу». Ctrl/Cmd+Enter = создать.
  Закрытие черновика с содержимым — сначала подтверждение внутри окна.
- Статусы: добавить/удалить/переименовать/перекрасить/переставить.
  При создании статуса можно выбрать «после какого статуса». Колонку можно перетащить за
  заголовок или сдвинуть стрелками ← →. В настройках — стрелки ↑ ↓.
- Стримлайны: «Нет» / «Тип» / «Агент» (ведёт агент vs делаю сам).
- Сабтаски пользователю понравились как есть: чекбокс, название, «▶ Агент», живой лог агента.
- Кнопка «+» справа снизу: записать мысль, сгенерировать с AI, сохранить в идеи, сделать задачей.

## Технические решения

- Только локально, один пользователь, без авторизации. Слушать `127.0.0.1`.
- Агенты подключаются через **MCP**, чтобы работал любой агент в любом харнесе, не только Claude Code.
- Агент меняет код в рамках задачи; при необходимости может ходить в другие места.

### Отступления от ARCHITECTURE.md при реализации

- **БД — встроенный `node:sqlite`** (Node ≥ 22.13) вместо better-sqlite3 + Drizzle: нет нативной
  сборки и install-скриптов (npm 11 их блокирует), `npm install` работает везде. Миграции — простые
  SQL-строки в `apps/server/src/db/migrations.ts`, версия в `PRAGMA user_version`.
- **Drag&drop — нативный HTML5**, как в макете, вместо dnd-kit: поведение и подсветка 1:1 с макетом,
  без лишней зависимости. Тач-экраны не поддерживаются (доска локальная, для десктопа).
- **Шрифты — локально через `@fontsource`**, доска работает без интернета.
- **Порт — `TRAKT_PORT`**, база — `TRAKT_DB` (по умолчанию `data/trakt.db`).
- **Ключ проекта** генерируется из названия, кириллица транслитерируется (`Мобильное…` → `MOB`),
  чтобы агенту было удобно писать `MOB-3`.
- **«Агент работает» на карточке** — только когда агент реально держит задачу (claim) или гоняет
  сабтаску. В макете это имитировалось для всех задач агента в статусах «в процессе».
- **Тумблер «Агент двигает задачи»** хранится на сервере (`app_settings.agentsPaused`), т.к. это
  правило для агентов, а не вид.
- **Агент и лиз.** Двигать и менять задачу агент может, только если она отдана агенту или он её
  взял (claim_task). Комментарий — всегда. Когда человек забирает задачу, лиз агента снимается.
- **Пауза** («Агент двигает задачи» выкл.) запрещает агентам переходы и автоподхват задач; прогоны,
  запущенные вами вручную, продолжаются.
- **Защита локального сервера.** Только Host/Origin 127.0.0.1/localhost, изменения — только с JSON-телом:
  чужая веб-страница в браузере не может дёрнуть доску или MCP.
- **Раннер (push).** Промпт уходит в stdin процесса (работает и в cmd на Windows, без ).
  «▶ Все агенту» — очередь: сабтаски по одной, каждая своим процессом и логом. «▶ Отдать агенту»,
  «Создать и отдать агенту» и перенос в дорожку «Ведёт агент» сразу запускают агента, если раннер
  настроен (иначе задачу возьмёт агент через MCP). Если агент не отчитался сам, сабтаска закрывается
  по коду выхода: 0 — готово, иначе — «не вышло», остаток очереди снимается.
- **Worktree — один на задачу** (ветка `trakt/PAY-12`, папка `data/runs/worktrees/PAY-12`), а не на
  каждый прогон: сабтаски одной задачи продолжают работу друг друга.
- **Имя агента в push-режиме** берётся из команды (Claude Code / Codex / Агент) и передаётся агенту в
  промпте: во всех вызовах MCP он указывает `agent`, чтобы доска узнавала «своего».

## История правок макета

1. v1 — первый макет: проекты, статусы, стримлайны по эпику/исполнителю/типу, 4 агента,
   правая панель задачи, приоритет, стори-поинты.
2. v2 — убраны стори-поинты, эпики, исполнители, выпадающие списки в задаче; окно по центру;
   статус-степпер; критерии под описанием; один обобщённый агент; добавлена «Срочность».
3. v3 — починены настройки (окно закрывалось от любого клика); выбор позиции статуса;
   «Срочность» удалена.
4. v4 — черновик задачи и кнопка «Создать задачу».
