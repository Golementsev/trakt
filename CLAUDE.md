# Тракт — правила для кодового агента

Простая локальная AI-native канбан-доска. Подробности — в `docs/`.
Перед работой прочитай `README.md`, `docs/SPEC.md`, `docs/DECISIONS.md`, `docs/ARCHITECTURE.md`,
`docs/MCP.md`, `docs/PLAN.md`. UI-эталон — `mockup/trakt.html`.

## Главное

- **Простота важнее полноты.** Пользователь просил простую доску. Не добавляй сущности,
  поля и настройки, которых нет в спеке. Если кажется, что что-то нужно, — спроси.
- **Отвергнуто навсегда (без явной просьбы не возвращать):** стори-поинты, эпики,
  исполнители, несколько именованных агентов, приоритет/срочность, выпадающие списки
  и выбор статуса внутри окна задачи, правая боковая панель для задачи.
- **Макет — эталон структуры и поведения.** Раскладка, тексты, порядок блоков в окне задачи — как в
  `mockup/trakt.html`. Визуальный стиль (цвета, типографика, отступы, иконки) пользователь заменил на
  спокойный «в духе Todoist» — эталон стиля `apps/web/src/styles/app.css`. Интерфейс на русском, адаптивный.
- **Одна правда на сервере.** Воркфлоу, права агента и события — только в `apps/server/src/domain`.
  REST и MCP — тонкие обёртки над доменом. Фронт не дублирует правила, а показывает ответ сервера.
- **Любой агент.** Не привязываться к Claude Code: интеграция через MCP, запуск — через шаблон команды.
  Источники агентов (кто запускается кнопкой, чем отвечает AI) — одни на доску, страница «Агенты».
  Как всё устроено — `docs/AGENTS.md`.

## Как работать

- Идём по этапам `docs/PLAN.md`. Не начинай следующий этап, пока пользователь не посмотрел текущий.
- Каждое изменение доменной логики — с тестом (Vitest).
- Перед тем как сказать «готово»: `npm run typecheck`, `npm test`, открыть приложение и проверить руками
  сценарий этапа.
- Слушать только `127.0.0.1`. Никакой авторизации. БД — `data/trakt.db` (в `.gitignore`).
- Коммиты маленькие, по смыслу. Сообщения на английском.

## Команды (после этапа 0)

```
npm install
npm run dev        # сервер :4700 + Vite
npm test
npm run typecheck
npm run build && npm start
```
